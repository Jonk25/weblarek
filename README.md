# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

Приложение оперирует двумя основными типами данных: **товаром** и **покупателем**.  
Их типы описаны следующими интерфейсами.

### IProduct — интерфейс товара

```typescript
interface IProduct {
  id: string;          // Уникальный идентификатор товара
  description: string; // Описание товара
  image: string;       // Изображение товара
  title: string;       // Наименование товара
  category: string;    // Группа товара
  price: number | null; // Цена, может быть null, если цена не указана
}

IBuyer — интерфейс покупателя
interface IBuyer {
  payment: TPayment | null; // Способ оплаты; null если не выбран
  email: string;            // Адрес электронной почты
  phone: string;            // Номер телефона
  address: string;          // Адрес доставки
}
Интерфейс IBuyer описывает данные, которые покупатель вводит при оформлении заказа. Поле payment допускает значение null, когда способ оплаты ещё не выбран.

Модели данных
Классы этого слоя отвечают за хранение и работу с данными в соответствии с паттерном MVP.

CatalogModel — каталог товаров
Назначение и зона ответственности:
Хранение списка всех доступных товаров и товара, выбранного для детального просмотра. Предоставляет методы для получения товаров и управления предпросмотром.

Конструктор:
constructor() — не принимает параметров. Инициализирует пустой массив товаров и устанавливает preview = null.

Поля класса:

products: IProduct[] — массив всех товаров каталога.

preview: IProduct | null — товар, выбранный для отображения в модальном окне.

Методы класса:

setProducts(products: IProduct[]): void
Сохраняет переданный массив товаров в поле products.

getProducts(): IProduct[]
Возвращает текущий массив товаров каталога.

getProductById(id: string): IProduct | undefined
Находит и возвращает товар по его идентификатору. Если товар не найден, возвращает undefined.

setPreview(product: IProduct): void
Сохраняет переданный товар в поле preview для последующего детального просмотра.

getPreview(): IProduct | null
Возвращает товар, сохранённый для предпросмотра.

CartModel — корзина покупателя
Назначение и зона ответственности:
Управление списком товаров, добавленных пользователем в корзину. Подсчёт общей стоимости и количества товаров.

Конструктор:
constructor() — не принимает параметров. Инициализирует пустой массив товаров.

Поля класса:

items: IProduct[] — массив товаров, добавленных в корзину.

Методы класса:

getItems(): IProduct[]
Возвращает текущий массив товаров в корзине.

addItem(product: IProduct): void
Добавляет переданный товар в корзину.

removeItem(id: string): void
Удаляет товар с заданным идентификатором из корзины.

clear(): void
Полностью очищает корзину.

getTotalPrice(): number
Возвращает сумму цен всех товаров в корзине (игнорирует price = null).

getTotalCount(): number
Возвращает количество единиц товара в корзине.

hasItem(id: string): boolean
Проверяет, находится ли товар с указанным id в корзине.

BuyerModel — данные покупателя
Назначение и зона ответственности:
Хранение и валидация данных, вводимых покупателем при оформлении заказа. Гарантирует, что переданные на сервер поля будут корректны.

Конструктор:
constructor() — не принимает параметров. Инициализирует payment = null и пустыми строками поля email, phone, address.

Поля класса:

payment: TPayment | null — выбранный способ оплаты.

email: string — адрес электронной почты.

phone: string — номер телефона.

address: string — адрес доставки.

Методы класса:

setPayment(payment: TPayment): void
Сохраняет выбранный способ оплаты.

setEmail(email: string): void
Сохраняет email.

setPhone(phone: string): void
Сохраняет номер телефона.

setAddress(address: string): void
Сохраняет адрес доставки.

getData(): IBuyer
Возвращает объект с текущими данными покупателя (включая payment, который может быть null).

clear(): void
Сбрасывает все поля к начальным значениям (null и пустые строки).

validate(): TBuyerErrors
Проверяет корректность заполнения полей. Возвращает объект ошибок, где ключами являются имена полей с ошибками, а значениями — текст ошибки (например, { email: 'Укажите email' }). Если все поля валидны, возвращает пустой объект. Тип ошибок TBuyerErrors определён в src/types/index.ts:
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;.

Правила валидации:
Поле считается валидным, если оно не null и не является пустой строкой (после удаления пробелов). Для payment допустимо только значение из TPayment, null рассматривается как ошибка.

Слой коммуникации
ShopApi — класс для взаимодействия с сервером
Класс ShopApi отвечает за обмен данными с backend-сервером интернет-магазина.
Использует композицию: получает через конструктор экземпляр, реализующий интерфейс IApi, и делегирует ему выполнение HTTP-запросов.

Конструктор:
constructor(api: IApi) — принимает объект с методами get и post.

Методы класса:

getProductList()
Параметры: отсутствуют.
Возвращаемый тип: Promise<IProductListResponse>.
Описание: Выполняет GET-запрос на эндпоинт /product/ и возвращает промис с объектом, содержащим массив товаров (свойство items).

postOrder(order: IOrderRequest)
Параметры: order — объект заказа, содержащий способ оплаты, контактные данные, список идентификаторов товаров и итоговую сумму.
Возвращаемый тип: Promise<IOrderResponse>.
Описание: Отправляет POST-запрос на эндпоинт /order/ с переданным объектом заказа в теле запроса. Возвращает промис с объектом, подтверждающим оформление заказа (содержит id заказа и итоговую сумму total).

Зона ответственности:
Изоляция деталей HTTP-обмена от остального приложения. Все запросы к серверу проходят только через этот класс.

Слой представления (View)
Классы этого слоя отвечают за отображение данных и взаимодействие с пользователем. Все представления наследуются от базовых классов и следуют принципу реактивности: они не хранят бизнес-логику, а только рендерят данные, полученные через render(), и эмитят события о действиях пользователя.

Базовые классы представлений
Класс Component<T>
Базовый класс для всех компонентов интерфейса.

Конструктор:
constructor(container: HTMLElement) — принимает корневой DOM-элемент компонента.

Поля:
container: HTMLElement — ссылка на корневой элемент.

Методы:
render(data?: Partial<T>): HTMLElement — принимает данные и возвращает отрендеренный DOM-элемент. В наследниках предполагается переопределение этого метода для заполнения конкретных полей.
Класс EventedComponent<T>
Расширяет Component, добавляя поддержку событий через EventEmitter.

Поля:
protected events: EventEmitter — экземпляр брокера событий.

Методы:
protected emit<U extends object>(event: string, data?: U): void — эмитит событие (доступно только внутри класса и его наследников).
public on<U extends object>(event: string, cb: (data: U) => void): void — подписка на событие (публичный метод для Presenter).

Класс BaseCard
Базовый класс для карточек товаров. Наследуется от EventedComponent<IProduct>.

Поля:

Методы:
set title(v: string) / set price(v: number | null) — сеттеры для обновления DOM.
getData(): Partial<IProduct> — возвращает сохранённые данные товара.

Класс ProductCardBase
Промежуточный класс для карточек с расширенным функционалом (картинка, категория, кнопка). Наследуется от BaseCard.

Поля:
protected imageEl: HTMLImageElement
protected categoryEl: HTMLElement
protected buttonEl: HTMLButtonElement | null

Методы:
set image(v: string) / set category(v: string) — сеттеры для изображения и категории.
Класс BaseForm<T>
Базовый класс для форм. Наследуется от EventedComponent<T>.

Поля:
protected submitBtn: HTMLButtonElement — кнопка отправки.
protected errorsEl: HTMLElement — контейнер для сообщений об ошибках.

Методы:
set errors(v: Record<string, string>) — отображает ошибки и блокирует/разблокирует кнопку.

protected abstract populateFields(values: Partial<T>): void — заполнение полей данными.

Принцип реактивности в Views
Все представления следуют единому паттерну:
Получение данных: Вызов render(data) → заполнение полей через сеттеры → возврат container.
Отправка действий: Пользовательское взаимодействие → эмит события через emit() → обработка в Presenter.
Обновление состояния: Изменение модели → событие model:changed → вызов render() или set errors в представлениях.
Представления не хранят бизнес-данные и не выполняют валидацию. Вся логика вынесена в Model и координируется через Presenter.
